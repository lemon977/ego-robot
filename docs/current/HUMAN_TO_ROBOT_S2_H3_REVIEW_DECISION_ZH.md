# Human→Robot S2 H3 外部复核后的执行决定

本文是对外部技术复核的项目内执行解释，不是新的运行收据，也不修改 H3 的机器事实、旧 attempt、质量门或采用状态。

## 当前结论不变

- 正式产品候选：结构完成 `4/4`，质量通过 `0/4`，采用 `0/4`。
- 031 正式 renderer 已忠实消费实际 q/FK 与真实连接件；这不证明腕目标、安装物理精度或动作质量正确。
- 031 full-pose 腕目标仍有约 `77.5 / 104.4 mm` 的 P50/P95 残差；position-only 与旧 two-stage 均保持拒绝。
- 007 局部 Clean 的长线缆仍有残留；031 以外没有合格 Depth；Contact/Robot R1 仍为 `0 screened / 0 executed / 0 adopted`。
- 031 遮挡的 `736/3269` 是原始归属切换计数，不是错误率；known coverage 也不是准确率。

## 本轮剩余执行决定

1. H6 前不新增全片 HaWoR、Clean、IK、Depth 或 HuRo 运行；只允许读取既有数组、验证产物、冻结组件和完成收据闭合。
2. “位置硬约束＋有证据的分级方向目标”与旧 two-stage 在方法合同上可能不同，但当前 031 IK 故障包已经使用两轮修复额度。本 S2 不改名启动第三次 IK；该方向仅作为后继候选，必须重新登记固定窗口、方向资格、停止门和预算。
3. 007 只有在冻结的原图证据能形成唯一、持续、可拒绝的 top-1 线缆实例，并证明支持/传递存在可修差异时，才允许后继的一次小窗 ProPainter。当前没有该冻结证据，因此 S2 不重跑。
4. 不为 031 时序遮挡追认新阈值。H3 数字只保留为开发诊断；后继若继续，必须先建立合法的跨帧表面对应，再区分真实穿越、边界变化、几何不确定和不可解释翻转。
5. 连接件保持 `UNVERIFIED_VISUAL_GEOMETRY_ONLY`，除非已有批准的碰撞几何及覆盖验证；视觉网格进入 RGB/depth/ID 不能继承为整机碰撞通过。
6. Local/HuRo 只报告共同目标下的限定数字差异和各自全时间轴覆盖/失败，不宣布真实人体精度、实机优劣或总体赢家。

- 保留但不采用：031 full-pose、position-only、two-stage，031 实片遮挡候选，007 Clean 候选，以及四条正式产品候选。

- H6 决定是否停止新增全片算法；H9 冻结本轮实际组件组合。两者都不能把 `0/4` 质量通过改写成产品成功。

## 七问外部复核的吸收结果

两份后续外部复核意见一致：当前 S2 继续按原时间门收尾；下一项若获单独登记，只建议先做一个有限的 031 小窗后继，不同时启动线缆、遮挡、Contact 或连接件碰撞五个方向。外部复核是方法建议，不是项目机器证据。

推荐后继的最小边界为：

```text
对象：play_cards_0915_031，frame 66–81，右臂
预算：单独登记后最多3小时
方法：腕位置真硬约束 + 求解前冻结的方向资格
扩展：不自动扩全149帧；不自动切换到其他方向
```

开始前必须先闭合以下前置，任何一项缺失都应有限停止：

1. 从真实质量合同追溯位置门 `tau_p` 的参考点、坐标系、单位、范数和判定函数；不得把 `residual / 0.005` 一类损失尺度当质量门，也不得把欧氏球约束偷换成逐轴盒约束。
2. 方向资格在读取 IK 输出前冻结，只能依据掌部来源、解剖侧别、掌基构造、非退化性、符号稳定和已有独立图像代理；不得按哪个方向更容易求解事后选轴。
3. 证明新合同与旧 two-stage 可触发不同结果：旧软折中可牺牲位置时，新合同不得把超过 `tau_p` 的输出发布为合格；同时必须有位置可行见证，避免“永远失败”也通过测试。
4. 固定 68.4 mm 完整安装、相机/base/placement、URDF/mesh、轴/限位、手指 q 和已有声明碰撞范围。连接件碰撞仍未验证的事实必须显式保留，不能借此后继升级。

后继逐帧重算 FK 并记录位置约束、支持方向误差、完整方向诊断、限位、声明范围碰撞、真实时间连续性和失败原因。只有位置成立或方向/碰撞资格不完整时，最多发布 `POSITION_FEASIBILITY_DIAGNOSTIC`；只有预冻结支持方向、位置、连续性及声明范围约束均通过时，才可发布 `PARTIAL_DIRECTION_MOTION_CANDIDATE`。两者都不是旧 full-pose、产品、控制、部署或外部真值通过。

其他四问保持如下后继边界：

- 007 线缆：先建立一条具有绝对证据、领先间隔、持续身份和拒绝条件的 top-1 实例；不成立就不调用 Clean。
- 031 遮挡：Robot 可用刚性 link/FK 建立数字表面对应；移动牌面没有合法对应时保持不足。旧 `736/3269` 与新同表面指标不得混分母。
- Contact/R1：下一次应先做逐级漏斗。当前仍是 `NOT_SCREENED`；只有实际评估指定范围后，才可能写 `NO_ADMISSIBLE_WINDOW_ESTABLISHED`。
- 连接件碰撞：视觉网格与简单 fixture 不能证明正式后端覆盖。必须核验真实调用栈和实际网格，或使用已批准并证明覆盖的保守包络。

推荐后继顺序为：031硬位置/方向 IK、007持续线缆、连接件碰撞覆盖、031遮挡时序、Contact/R1。这个顺序不是并行启动清单；若前置不成立，先准确终态化，不自动消费下一方向预算。
