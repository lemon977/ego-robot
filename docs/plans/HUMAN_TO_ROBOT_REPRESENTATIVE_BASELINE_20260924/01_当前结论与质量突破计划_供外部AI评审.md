## 3. 本次新核对得到的具体原因

### 3.1 Chips机械臂最大跳变有确定的初值重置触发路径

`full_robot_review_v2.py` 当前保存结果后执行：

```python
seed = result.x.copy() if result.success else neutral[side].copy()
```

Chips物理左臂保存数据：

| 帧 | solver_success | nfev | 腕位置残差mm | 完整旋转残差° |
|---:|---|---:|---:|---:|
| 157 | true | 31 | 近0 | 近0 |
| 158 | false | 80 | 3.4406 | 0.8533 |
| 159 | true | 44 | 近0 | 近0 |

158帧触及求解次数上限，下一帧被重置为中立初值；158→159最大单关节变化2.1517rad。158帧的数值残差本身仍小于当前20mm/15°门。代码与数组共同证明这条重置路径确实发生，尚未用反事实重跑证明它解释全部跳变。

拟首先验证的修复：区分“优化器达到停止条件”和“有限、限位内、可用于下一帧初始化的解”。保留158帧原solver失败事实，不自动授予该帧质量通过；下一帧的初值不因非致命max_nfev退出无条件跳回中立。真正缺失、gap、非法数值仍按冻结规则重置。先固定156–160及正常窗验证，再同配方全片。

这比再调平滑权重更直接。旧continuity_weight=0.5候选已证实：左臂最大步长2.1517→0.4280rad，但跟踪通过帧左351→281、右295→166；该候选继续拒绝，不再权重扫描。

Poker右臂99→100最大单关节变化1.9680rad；保存旧R0没有solver_success/nfev，所以不能直接断言与Chips同因。只追溯实际生产者的初始化/求解退出链，并用相同固定窗口验证。Poker右手104→105手指最大步长约0.52rad，属于独立的手指来源/retarget检查，不随机械臂修好而自动通过。
