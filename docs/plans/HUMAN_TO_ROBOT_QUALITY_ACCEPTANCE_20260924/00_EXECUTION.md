# Human→Robot Baseline v1：质量修复、全片验收与采用交付

本文件是本轮唯一执行合同，产品分母固定为 007、031、0902_103、0902_042。目标优先使 Poker 0902_042 的 171 帧产品获得独立技术质量通过，用户验收指定 SHA 后才可记为采用。Chips 0915_042 仅作初始化反事实；031 不运行新 IK；HuRo 不运行新求解。任务限时 10 小时，从登记收据 T0 计时。

1. Motion：区分 `solver_success`、`seed_usable` 和 `tolerance_pass`；合法的 SciPy `status=0` 解可作同连续段下一帧初值，不能改写当前帧的收敛、质量或覆盖。先固定 Chips 156–160 与 0–15 作单变量反事实，成立才重算依赖后缀；Poker 96–111 先追真实生产者，手指 104→105 另追首个错误层。原位置 20 mm、完整旋转 15°及原限位/碰撞门不放宽。
2. Scene：Poker 76–91 是主窗口，0–15、155–170 是控制窗。人体/设备删除、当前帧可见牌面保护、UNKNOWN 冲突和逐 reference 排除支持须在实际模型张量中核验。一次固定配方小窗，过原门且时间足够才扩全 171 帧。结构合法但质量拒绝的 Clean 只作离线失败候选。
3. Sensor：复用 097/098/101 的共同后端与已有局部碰撞收据。由 097 的 MANUS25→21→Kai22 q→独立 FK/限位/局部质量→H50→现有消费者逐项授予资格；同规则扩 098/101。腕世界资格与局部手形分开，optimizer 更新为零。
4. 发布：候选、独立技术评价、原四片计数、指定 SHA 的用户审阅与采用分别记录。正式 CLI 绑定实际组件，合格 Clean/运动/遮挡等必需门逐项检查；UNKNOWN 不算正确。Contact/R1 不是基础产品总门。0902 sourceIndex0 矫正域不得混用 0915 sourceIndex1 域。用户未回复只影响采用，不否定技术通过。

所有旧输入/产物/收据只读，新文件与缓存仅在项目内。CPU 软上限 8 线程、重任务最多 2 个、GPU 单租约。H0–H3 做根因反事实与固定窗；H3–H6 做已准入全片；H6–H8 独立技术验收并提交用户审阅；H8–H10 收尾、重载、全解码、SHA、resume 与导航。时点不是等待门，提前就绪就提前继续。失败局部终态不阻塞其他 READY 工作，不因文件数或渲染成功宣称质量通过。

全部保持 OFFLINE_VISUAL；`training_eligible=false`、`control_ground_truth=false`、`physical_deployable=false`、`external_metric_authority=false`，学习资格仅按真实消费者/字段/窗口发布。
